Tileception: greeter

An optional greetd greeter laid out like a Tileception desktop: the login screen is three tiles, the users are a tab group, actions live in the launcher, and errors arrive as notifications. Logging in turns the tiles into your windows, and locking folds them back. Click the screen to try it, or follow the tour on the right.

Tour

    How it behaves

    Details the demo only hints at.

    Users

    • One user: no tab bar. The login tile shows the name and the field directly.
    • Many users: the tab bar scrolls, and the launcher lists "Log in as …" for everyone, so typing a name always works.
    • Hidden users and system accounts stay hidden. The + tab takes any username.
    • The last user and each user's last session are remembered in the greeter's own state file.

    Feedback

    • Wrong password: the field shakes and clears, and a notification with a danger stripe counts the attempts.
    • PAM messages (expired password, account locked, fingerprint prompts) arrive as notifications too, or as a second field in the login tile when PAM asks a question.
    • Caps Lock and the keyboard layout show in the hint line and the bar.

    Lock screen

    • The same three tiles, so locking is a fold rather than a cut.
    • No window content or notification text before unlocking: only counts, and media controls without the title.
    • The launcher still has power actions, media, and the keyboard layout.

    Panels

    • The tile tree is configurable. An admin can drop the Clock tile, or add a message-of-the-day or accessibility tile.
    • Panels lay themselves out with tileception-core, so they split, resize and nest like windows.

    Accessibility

    • Everything works from the keyboard. The launcher also has toggles for screen reader, larger text and high contrast.
    • With reduced motion, the morphs become short fades.

    Screens

    • Only the first output is lit today. Later, the greeter goes on the primary output and the others show the wallpaper.
    • Panel sizes follow output scale, and the layout splits along the longer side, so portrait screens stack the tiles.

    Per-user looks: where accents and wallpapers come from

    The greeter runs as the greeter user before anyone logs in. It can't read ~/.config, and the home directory may be encrypted.

    Your sessionWhen Tileception starts and whenever its config reloads, it puts together a greeter card: accent, accent_end, colour_scheme, and a downscaled wallpaper (at most the screen size, JPEG).
    →
    Published to a shared placeAccountsService, where avatars (Icon) already live. Tileception adds an extension interface, org.tileception.Greeter, holding the colours, plus the standard BackgroundFile. The wallpaper copy goes to /var/lib/AccountsService/… or /var/cache/tileception-greeter/<uid>/ through a small polkit-allowed helper, so it's readable without access to the home directory.
    →
    Greeter reads itThe greeter lists users and their cards, and fills anything missing from the fallback chain below. Opting out is one line in the user's config: [greeter] share = false. You'd then get your avatar and a generated accent.

    Fallback chain, per user

    1. Published cardAccent pair and wallpaper exactly as in the last Tileception session.
    2. AccountsServiceIcon for the avatar; BackgroundFile if another desktop set it and the file is readable.
    3. From the wallpaperA wallpaper but no accent: take two strong colours from the image and keep them only if they contrast enough with the text.
    4. From the usernameNothing published: hash the username onto a set of 8 tested accent pairs. It stays the same across boots and differs between people.
    5. System theme/etc/tileception/greeter.toml: the admin's wallpaper or flat Tide graphite. This is also used for the + tab and when per-user looks are turned off.

    Avatar fallback: AccountsService Icon, then the initial on the accent gradient. Wallpaper fallback (behind the tiles): generated mesh from the accent, then the system wallpaper, then flat graphite.

    Architecture

    A greeter mode of the compositor. greetd starts tileception --greeter, which runs the normal compositor with no clients and draws the panels with the same renderer and tile engine as the desktop. Logging in goes through greetd's IPC. tileception-auth stays the locker's PAM path.

    Why this gives the most room:

    • The greeter and the lock screen share their code, so the lock screen always matches.
    • The same [theme] keys and the same hot reload as the user config. An admin edits one TOML file.
    • Panels are tiles, so the tile tree itself is configuration: which panels exist, where they go, and how big they are.
    • Tabs, the launcher, notifications and the bar are the desktop's own components, so they look identical and get fixes for free.

    The login morph is a handover. The greeter process ends and the session's compositor starts. To keep it seamless, the greeter passes its final layout to the session, the session draws those same three tiles on its first frame, and then animates them into windows. The hard part is a flicker-free DRM master handover. A short fade is an acceptable fallback. Locking happens inside the session, so that morph has no such limit.

    Alternative: a separate GTK4 greeter styled with CSS. Anything is possible visually, but it would match Tileception only as long as someone keeps the CSS in step, it can't share the locker, and the login handover is a hard cut.

    # /etc/tileception/greeter.toml
default_session = "tileception"
hidden_sessions = ["tileception-nested"]
hidden_users = ["backup"]
users_as = "tabs"           # tabs | tiles
clock_format = "%H:%M"

[panels]
# Columns of rows, sized by ratio. Panels: login, clock,
# session, motd, accessibility.
columns = [["login"], ["clock", "session"]]
ratios = [1.75, 1]

[per_user]
accent = true
wallpaper = true
wallpaper_fallback = "generated"   # generated | system | flat

[theme]                     # same keys as the session's [theme]
accent = "#2bd4a7"
accent_end = "#5c8ff2"
wallpaper = "/usr/share/backgrounds/tide.jpg"

[lock]
show_media = true
show_notification_count = true
