Citrus in Tileception

Citrus converts and edits files while you drag them: pick up a file, press a key, release it on an option, and a new file appears beside the original. On most Linux desktops it has to guess at the drag from outside. Tileception doesn't have to guess. It already brokers every drag, reads the file list as the drag starts and draws a card for it (drag.rs). So Citrus can live inside the compositor rather than float above it.

Five ways to do that, all in Tide. They share one key: hold Super mid-drag. Citrus uses Shift, Ctrl and Cmd on macOS, but on Linux Shift and Ctrl already change a drag between move and copy, and Super is Tileception's own.

How it goes

  • Drag a file and hold Super. The drag card slides into the hub and the wheel opens around it.
  • Tap Super again to cycle Convert, Tools and Send, shown as the arc above the ring.
  • Release on a slice. The wheel stays until you let go of the file, like Citrus.

Why

  • Anyone who knows Citrus already knows this. Nothing to learn.
  • Fixed slice positions build muscle memory: PNG is always at twelve o'clock.

Watch out

  • Eight slices is the ceiling. Video and documents need more formats than fit.
  • Near a screen edge the wheel has to shift away from the pointer.

How it goes

  • Drag, hold Super: the drag card turns into the file chip in a launcher field.
  • Type to filter. The field edits like every other Tileception field (word moves, Ctrl+U, compose keys).
  • Drop on a row, or let go and press Enter. Tab chains steps: strip location, then WebP.
  • No drag at all: select files, open the launcher, type convert.

Why

  • No limit on options. Video's forty formats are a few letters away.
  • Sizes are estimated before you commit, in the same quiet mono as other answers.
  • Reuses the launcher, its ranking and its history: the formats you pick often rise to the top.

Watch out

  • Typing while holding a mouse button is awkward. Most will let go first, which is why Enter has to work after release.

Arrive as

contextual

The upload form only takes JPG or PNG, so the file arrives as a JPG.

How it goes

  • Drag over a window: the tile gets a dashed teal outline and a card naming what arrives.
  • Drop, and the window receives a fresh converted copy. The original never moves.
  • Tiles you pass but don't hover show their guess faintly, so you can pick the right target from afar.

Why

  • Zero extra keys for the common case. The compositor sees the target's accepted types during the drag and can hand it a converted file instead.
  • Same idea across machines: a handoff drag to a Mac-less laptop can arrive as JPG.

Watch out

  • Most apps accept text/uri-list and nothing more specific. Guesses then come from per-app rules, which need curating.
  • Silent conversion surprises people. The card has to be loud enough to read before the drop.

Peel

on brand, wild

Tile it, nest it, zoom it, for files. Super mid-drag and the camera zooms into the drag card, which opens into its own little tree of tiles: Convert, Tools, Send. Hover a group and the camera flies one level deeper. Every choice is a big tile, never a sliver of a ring.

Click a tile to zoom in (in Tileception, hovering for a moment does it). Click the path to zoom out.

How it goes

  • Drag, hold Super: the camera zooms from the desktop into the card, the same flight as zooming into a tile.
  • Rest on a group to fly in. Move to the frame's edge, or scroll back, to fly out.
  • Drop on a leaf to run it. The camera flies back to where you were and the new file is selected.

Why

  • Uses the gesture Tileception users already have in their hands. The minimap even shows how deep you are.
  • Big targets at every depth, so it scales to video and archives without cramming.
  • Group sizes can follow use: the formats you pick most get the larger tiles.

Watch out

  • Hover-to-enter needs a careful dwell time, or crossing a tile on the way somewhere else zooms you in.
  • Changing tile sizes breaks muscle memory. Keep positions stable and only grow them.

Duck

wildest

The rubber duck already wanders the bottom of the screen. Drop a file on it and it holds it in its beak, then offers what it thinks you want, with the three likeliest options on number keys. It's the friendliest door for people who will never learn a modifier key.

How it goes

  • Drop a file on the duck (it waddles toward a drag that comes close). It grabs the file and its bubble opens.
  • Press 1–3 or click. Space opens the full drop palette from concept 2.
  • While it works, the duck sits on the file. When it's done it drops the new file back into the folder it came from.

Why

  • No hidden key to discover: if you can see the duck, you can find this.
  • Suggestions come from local rules (file type, size, what you picked last time). Only "Transcribe" goes to Doctor's agent, and it says so.

Watch out

  • The duck is off for many people. This can only be a second door, never the only one.
  • Personality wears thin. One short line, then options; no jokes on the tenth file.

What every concept shares

The way in differs; what happens after the drop stays the same, so the concepts can be mixed.

Where it plugs in

  • drag.rs already reads the file list and draws the card. That's the hook for every concept.
  • The conversions themselves come from Citrus's own command line, run as a plugin over MCP, so Tileception doesn't grow its own converter. The plugin API needs one new hook: actions offered for a dragged file.
  • A missing Citrus means no wheel, no palette rows and no error. Drags behave as they do now.

My pick

Ship first: Drop palette

It reuses the launcher and its text field, scales to every format and works without a drag. Lowest risk, most reach.

Then: Peel

The one only Tileception could make. Build it once the palette's actions exist, since it shows the same list as tiles.

Later: Arrive as

Great when it guesses right, so it needs per-app rules first. The duck can borrow the palette whenever someone wants it.
